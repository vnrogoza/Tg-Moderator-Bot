# Чистая архитектура Telegram AI Модератора на Python

Полный перевод бэкенда и логики бота на Python, удаление дублирующихся TypeScript-файлов из серверных папок, добавление персистентности кармы (SQLite) и структурирование чистого Python-проекта.

---

## Подтверждённые решения пользователя

> [!IMPORTANT]
> **Выбор пользователя**: «Сделать проект чисто на Python и удалить весь TypeScript».
> - Серверная и бот-логика будет функционировать исключительно на Python (`server.py`, `backend/*.py`, `bot.py`).
> - Все дубликаты и неиспользуемые файлы TypeScript в `server/` и `backend/` удаляются.
> - Веб-интерфейс симулятора и панели управления (React + Tailwind) сохраняется в собранном виде (`dist/`) и отдаётся напрямую сервером Python без участия Node.js бэкенда.

## 1. Обзор и концепция

Проект представляет собой **автономную платформу модерации Telegram-сообществ на базе ИИ Google Gemini 3.8 и Python**, включающую:
1. **Telegram-бот модерации (`bot.py` / `backend/telegram_bot.py`)**:
   - Автоматический скоринг сообщений от -5 до +5.
   - Фильтрация обсценной лексики и оскорблений с моментальным удалением.
   - Накопление персональной кармы участников в постоянной базе данных SQLite.
   - Автоматический мут при карме $\le -10$ и перманентный бан при $\le -25$.
   - Административные команды: `/rating`, `/stats`, `/unban`, `/unmute`.
2. **Интерактивная панель управления и симулятор (`server.py` + веб-интерфейс)**:
   - Симулятор чата с тестовыми персонажами (Тролль, Позитив, Эксперт).
   - База пользователей с детальными карточками нарушений и ручным управлением статусами.
   - Аналитика тональности, статистика нарушений и интерактивный тестер фраз.
   - Единый сервер на стандартной библиотеке Python, не требующий сложных настроек.

## 3. Ключевые архитектурные решения

### Решение 1: Ликвидация дублирования папок (`server/` и `backend/`)
- **Проблема**: в проекте одновременно существовали папки `server/` и `backend/`, содержавшие одинаковые наборы файлов и мусорные копии `.ts` и `.py`.
- **Выбранный подход**: 
  - Удалить устаревшую папку `server/` и все серверные `.ts` файлы (`server/store.ts`, `server/geminiModerator.ts`, `server/telegramBot.ts`).
  - Очистить папку `backend/`, оставив только чистые Python-модули:
    - `backend/store.py` (хранилище с поддержкой SQLite)
    - `backend/gemini_moderator.py` (модерация Gemini 3.8 + регулярный fallback)
    - `backend/telegram_bot.py` (Telegram Bot API клиент)
  - Главный веб-сервер: `server.py`.
  - Автономный бот: `bot.py`.

### Решение 2: Добавление постоянного хранения (SQLite)
- **Проблема**: при перезапуске сервера или бота память очищалась, и карма пользователей сбрасывалась до исходных демо-данных.
- **Выбранный подход**: использовать встроенную в Python стандартную библиотеку `sqlite3`.
  - Файл базы данных `moderator.db`.
  - Таблицы: `users` (карточка, карма, статус, время мута), `messages` (история модерации), `settings`.
  - При первом запуске база автоматически наполняется начальными демонстрационными данными.

### Решение 3: Оптимизация вызовов Gemini API
- **Проблема**: вызов ИИ на каждое сообщение приводит к быстрому исчерпанию бесплатных квот Gemini (15 RPM).
- **Выбранный подход**: двухуровневая фильтрация:
  1. Локальный regex-фильтр (0 мс, 0 токенов). Если обнаружен явный мат — сообщение немедленно удаляется со штрафом без расхода квот API.
  2. Запрос к Gemini 3.8 Flash для неочевидных контекстных сообщений, сарказма и конструктивной помощи.

               ▼                              ▼

               ▼                             ▼

   └───────────────────────┘     └───────────────────────┘

### План выполнения:
1. **Удаление дубликатов и TypeScript-сервера**:
   - Удалить `server/` и все серверные `.ts` файлы из `backend/`.
   - Оставить чистую структуру `backend/` только с Python-модулями.
2. **Интеграция SQLite в `backend/store.py`**:
   - Реализовать автосохранение кармы, статусов и истории в `moderator.db`.
3. **Оптимизация `backend/gemini_moderator.py` и `backend/telegram_bot.py`**:
   - Обеспечить единое разделяемое хранилище между веб-симулятором и реальным Telegram-ботом.
4. **Конфигурация окружения**:
   - Обновить `package.json` и `Dockerfile` для поддержки чистого Python-запуска.
   - Проверить сборку `compile_applet`, запуск `server.py` и `bot.py`.
